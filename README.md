# صيت

منصة صيت لإدارة الطلبات والأقسام والموظفين والتسليمات والمحتوى

مبنية من المصدر المحلي لبرو فيجن مع المحافظة على المكونات ودورة العمل وإلغاء بوابة العميل واعتماد هوية صيت بالأحمر والأسود والأبيض

ابدأ من [تعليمات المشروع](AGENTS.md) و[سجل النتائج](docs/task-state.md)

## التشغيل المحلي

يتطلب Node.js 20 وnpm

```powershell
npm ci
npm run dev
```

يفتح الخادم على `http://127.0.0.1:5175`

عند تشغيل `npm run dev` دون إعداد Supabase تعرض المعاينة المحلية المحتوى الافتراضي وصفحة الدخول دون اتصال بقاعدة البيانات

تسجيل الدخول والطلبات الحقيقية ونسخة الإنتاج تحتاج مشروع Supabase مستقل لصيت ولا تتجاوز المعاينة أخطاء الاتصال إذا كانت إعدادات الخدمة موجودة

انسخ `.env.example` إلى `.env.local` واضبط قيم مشروع صيت فقط ثم أعد تشغيل الخادم

## دورة الطلب

- المشرف هو موظف مع تفعيل صلاحية التنسيق من الإدارة
- يسجل المشرف الطلب ويربطه ببيانات العميل ويوجهه للأقسام
- يستلم الموظف المهمة ويحدد موعده ويطلب البيانات من المشرف عند الحاجة
- يرفع القسم المخرجات ويراجعها المشرف ويعتمدها أو يطلب التعديل
- تحتفظ المنصة بالتقارير والمواعيد والأداء وسجل القرارات والدخول الإداري بالنيابة عن الموظفين
- بيانات العميل سجل مرجعي داخل النظام دون دخول أو دعوة أو إشعارات موجهة له

المعرّفات القديمة المرتبطة بجدول Auth تبقى مراجع داخلية لتوافق العلاقات والتقارير ولا تمنح العميل حق الدخول

## إعداد الخلفية

راجع [دليل الإعداد](docs/seet-setup.md) قبل ربط مشروع Supabase أو نشر أي مكون

## الفحوصات المركزة

```powershell
node --test tests/auth-access.test.js tests/account-onboarding.test.js tests/impersonation-service.test.js tests/seet-customer-record.test.js
node tests/seet-database.mjs
npm run build
```

فحص قاعدة البيانات يعيد تشغيل الترحيلات كاملة في PostgreSQL معزول باستخدام PGlite ويحاكي بنية Auth وStorage وخدمات الجدولة والشبكة دون إرسال رسائل

اختبارات المرجع الأخرى موجودة تحت `tests` وبعضها يحتاج بيئة المصدر أو لقطات وظائف غير منسوخة فلا تعتبر نتائجها مضمونة لنسخة صيت
