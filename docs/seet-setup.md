# إعداد صيت

## الحالة

النسخة المحلية مستقلة عن ملفات أسرار برو فيجن وربط Vercel وSupabase الخاص بها

ضُبط اتصال الواجهة في `.env.local` على مشروع صيت `hhdrtrrghntzhqrqdvlr` بالمفتاح العام المقدم من المستخدم بتاريخ 2026-09-21

طُبقت 94 ترحيلا على قاعدة صيت الحية ونجحت قراءة إعدادات المنصة وإنشاء الحساب التقني والدخول بالبريد والجوال عبر API المحلي

موصل Supabase وCLI المتاحان لا يملكان صلاحية إدارة المشروع لكن الوصول تم من ملف Chrome المسمى seetksa بعد تثبيت المستخدم الإضافة

## قاعدة البيانات

استخدم مشروع Supabase مستقل مخصص لصيت مع تعطيل التسجيل العام للمستخدمين

اضبط Site URL على عنوان صيت وأضف مسارات استعادة كلمة المرور المصرح بها فقط إلى Redirect URLs

تحقق من إصدار Supabase CLI وأوامره عبر `--help` قبل الربط ثم طبق ترحيلات `supabase/migrations` بالترتيب على مشروع صيت بعد مراجعة المشروع المستهدف

الترحيل `20260920112756_seet_staff_only_workflow.sql` يفرض دخول الفريق فقط ويتيح للمشرف المسؤول اعتماد التسليم والرد على الأقسام ويمنع جلسات العميل والدخول بالنيابة عنه ويقيد قراءات وكتابات الجداول وStorage

نُقلت إضافات برو فيجن حتى `20260921024000` مع تكييف قيد إشعارات العملاء وإضافة `20260921025000_seet_staff_parity.sql` للحفاظ على تسجيل المشرف للبيانات المستكملة منفصلا عن التوضيحات الداخلية

احتفظ بالحاويات الخاصة وRLS والمنح كما في الترحيلات ولا تجعل مرفقات الطلبات عامة

الفحص المحلي يشمل 94 ترحيلا لكنه لا يثبت إعداد Auth أو Storage أو Realtime أو Edge Functions على مشروع حي

المقارنة الحية للمرجع أثبتت 22 جدولا عاما محميا بـRLS وبث Realtime لجدول `work_notification_signals` وحاويات `work-files` و`client-logos` و`portfolio-assets` الخاصة و`platform-designs` العامة وعامل `work-notifications` النشط بالإصدار 17

تم تعطيل التسجيل العام وإنشاء الحساب التقني وضبط الحاويات الأربع عبر Storage API ونشر العامل وربط الجدولة ومفتاح تشغيله والتحقق حيا من RLS والتحديثات الفورية

المتبقي إعداد مزود واتساب والبريد بعد حسم المستخدم للقنوات المطلوبة ثم اختبار الوصول الفعلي ولا تعتبر استجابة العامل `503 not_configured` نجاح إرسال

## حساب الإدارة

أنشئ أول حساب إدارة من أدوات Supabase الإدارية الموثوقة واضبط `app_metadata.role` إلى `super_admin`

لا تستخدم `user_metadata` لإسناد الصلاحيات ولا تضع أي مفتاح سري في واجهة التطبيق

بعد تسجيل الدخول أنشئ الموظفين والأقسام وفعّل التنسيق على الموظف الذي يعمل مشرفا على الطلبات

إنشاء سجلات العملاء لا يرسل بيانات دخول ولا يحتاج خدمة رسائل أما دعوات الموظفين فتحتاج إعداد قنوات الإرسال الحالية

## الإعدادات

انسخ القيم الفارغة من `.env.example` إلى `.env.local`

متغيرا `VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY` فقط مخصصان للواجهة

`SUPABASE_SERVICE_ROLE_KEY` ومفاتيح البريد وواتساب و`ONBOARDING_ENCRYPTION_KEY` و`WORK_DISPATCH_SECRET` أسرار خادم

عامل `work-notifications` منشور ومفتاح تشغيله مستقل ومحفوظ في Edge Secrets ونقطة الإرسال مرتبطة بقاعدة صيت ولا تزال مفاتيح البريد وواتساب مطلوبة

لا تشغّل سكربتات إدارة المرجع بصورة عمياء ولا تنقل ملفات `.env.local` أو `.vercel` أو `supabase/.temp` من برو فيجن

## النشر والتحقق الحي

قبل النشر الفعلي تحقق من Auth وتعطيل التسجيل العام ومسارات الاستعادة وRLS وStorage والصلاحيات ودورة الطلب بحسابات اختبار مصرح بها

تحقق من الإشعارات الداخلية فقط ومنع وصولها للعملاء

لا تعتبر البناء المحلي أو PGlite دليلا على تفعيل الخدمات الحية

مرجع الأمان المستخدم [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security) و[وظائف قاعدة البيانات](https://supabase.com/docs/guides/database/functions)
